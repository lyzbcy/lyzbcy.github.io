# 追踪页面可用性改造设计

## 目标

在不改变营养和健身数据源的前提下，修复两个追踪页面的移动端横向溢出，并降低营养页的信息密度，让评分说明、长表与历史明细在手机和键盘环境中都可用。

## 页面结构

- 两页首屏、KPI 和主要趋势保持直接展示。
- 营养页的食物营养库和详细历史数据改为原生 `details/summary` 折叠区块，默认收起。
- 顶部健康评分保留；底部重复的“今日健康得分细分”删除，只保留折叠后的历史趋势。
- 评分问号改成真正的按钮，点击、Enter 和 Space 均可切换说明面板，Escape 与点击外部可关闭。

## 响应式规则

- 所有宽表由局部容器承担横向滚动，页面本身不得横向滚动。
- 宽表设置合理最小宽度，避免把九列内容压成不可读的小字。
- 手机端健康评分卡改为纵向结构，三列历史评分卡改为单列。
- 辅助文字最小字号提升到 12px；来源等次要字段至少为 11px。

## 数据与模板清理

- 删除营养页连续的 Markdown 分隔线。
- 健康得分历史只渲染有日期且分数大于零的记录。
- 清理重复评分内容和无用 CSS 类，避免同一结论出现两次。
- 健身页三张宽表统一采用相同的滚动与可访问性说明。

## 可访问性

- 折叠标题使用原生 `summary`，无需 JavaScript 即支持键盘。
- 评分按钮设置 `aria-expanded`、`aria-controls` 和清晰标签。
- 评分面板切换时同步无障碍状态，焦点样式可见。
- 表格滚动区域使用 `role="region"`、`tabindex="0"` 和说明标签。

## 验证标准

- 静态结构测试能验证折叠区、表格滚动、评分按钮、无效历史过滤和重复区块清理。
- 两页本地构建成功。
- 390×844 手机视口下页面无整体横向滚动，宽表可在自身区域内滚动。
- 桌面端首屏样式不退化；评分说明可通过鼠标与键盘开关。
